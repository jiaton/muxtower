# AGENTS.md — app

`muxtower-app`: a PWA for phones and desktops that connects to one or more muxtower daemons. Shows every agent session waiting on a human across all daemons (Inbox), a live terminal (or, for sessions without a screen, the structured conversation) per session with approve/deny/option buttons and an input bar, and Web Push when an agent needs attention. Talks only to daemon `/v1` APIs. Served by the daemon at `/` (recommended) or hosted separately as static files.

## Setup / Test / Run

- Install: `npm ci`
- Dev server: `npm run dev` (proxies `/v1` to `MUXTOWER_DEV_DAEMON`, default `http://127.0.0.1:8741`: the dev daemon, `muxtower serve --dev`, so it is same-origin; never the real hub on 8731)
- Tests: `npm test` (Vitest) · E2E: `npm run e2e` (Playwright)
- E2E stability: wait for the page's own state, never a fixed sleep (a chip chosen, a drawer open, a "Picked up"
  announcement, a row's place settled after a fold); never retry an action that toggles (Alt+F, a chip: retrying
  flips it back), so click a chip or open a drawer only while it isn't already chosen/open; dispatch a fast
  series (a trackpad swipe, wheel notches) from inside the page, as one round trip per event is stretched by a
  loaded runner; read a list's order with `expect.poll`, not once.
- Lint/typecheck: `npm run lint && npm run typecheck` (includes `npm run check:tokens`)
- Regenerate API types: `npm run gen:api` (reads `../openapi.json`)
- Route tree: `npm run routes` (also run by build/typecheck; `src/routeTree.gen.ts` is committed)
- Build: `npm run build` → `dist/` (`MUXTOWER_BASE=/sub/path/` for sub-path hosting; `MUXTOWER_APP_CONFIG` writes `dist/config.json`)
- Demo: `npm run dev:demo` / `npm run build:demo` → `dist-demo/` (the project site embeds it at `/demo/`; build with `MUXTOWER_BASE=/demo/`)
- Deploy: `wrangler.jsonc` (Cloudflare Workers static assets), `.github/workflows/pages.yml` (GitHub Pages)

## Stack

- Vite + React 19 + TypeScript (strict)
- UI primitives: shadcn/ui-style components (Radix + class-variance-authority + tailwind-merge) in `src/components/ui/`, written against our tokens rather than shadcn's color names
- Styling: Tailwind CSS v4; tokens in `src/styles/tokens.css` (`@theme`), light and dark
- Routing: TanStack Router (file routes in `src/routes/`)
- Server state: TanStack Query · Client state: Zustand (persisted) — Zustand only, no Context stores
- Contract: `openapi-typescript` types from `../openapi.json` + `openapi-fetch`
- Drag and drop: dnd-kit (`@dnd-kit/core`, `sortable`, `modifiers`), e.g. the chip row's order (`project-chips.tsx`) and the list's projects (`project-sort.tsx`); `components/ui/sortable.tsx` gives its sensors (a mouse on a handle, a finger after `press.ts`'s hold, Space/arrows/Space), reduced motion and the ⋮⋮ `DragHandle`
- Dates: `react-day-picker` (one month, keyboard and screen-reader ready), drawn in our tokens by `components/ui/date-picker.tsx` (no stylesheet of its own); no hand-rolled calendar
- Standard interactions (drag and drop, sortable lists, virtualised lists, gestures beyond our simple swipes) come from a maintained open-source library (dnd-kit and the like), not hand-rolled code; a new one's bundle cost is said in its commit
- Terminal: our own view (`features/terminal`): ANSI → HTML lines (`lib/ansi.ts`) in a natively scrolling box, diffed line by line (`features/terminal/lines.ts`); no xterm.js. Non-ASCII text gets exactly the cells tmux gives it (`lib/cell-width.ts`), so every line adds up to the pane's columns: a CJK character is its fallback font scaled to exactly two cells (`term-wide`, the scale measured in the browser by the terminal view), an emoji or other wide symbol a 2ch box, other runs a box their width in `ch`, so columns line up whatever fallback font draws it; ASCII is drawn in the JetBrains Mono the app ships (`src/assets/fonts/`, Regular and Bold, OFL), since a browser with no monospace font draws `monospace` proportionally · PWA/push: `vite-plugin-pwa` (injectManifest, own service worker). App and notification icons: SVG sources (`public/icon.svg`, `scripts/icons/`) rendered to the PNGs in `public/` by `npm run icons` (commit both); Android needs PNGs to install the app and to show its notifications under its own icon
- Terminal fit (`features/terminal/fit-guard.ts`): a fitted pane is resized once its view settles (250 ms). `FitGuard` drops a size equal to the last and a bounce back to the one before within 10 s (a scrollbar coming and going), but only for content: a deliberate frame change (`watchFrame`: window or viewport resize, `fullscreenchange`, rotation, a layout switch, the drawer) always fits, even back. Each fit logs `[terminal] fitted to CxR (frame: <why>|content)`.

### Terminal glyphs: every class has one rule

The terminal view draws each glyph by its class. **A new rendering issue becomes a fixture plus a class
rule, never a one-off patch**: a fixture in `src/features/terminal/glyph-fixtures.ts` (made-up content, in
tmux's cells) that shows it, checked by the pixel suite `e2e/glyphs.spec.ts` (`make glyphs`; CI runs it
before every release: each fixture at 46 and 96 columns and at 1×, 2× and 2.6× pixels, no seam between
solid cells, no gap along a vertical line, text within 0.5 px of its cells at a row's end), then a rule for
its whole class below. A row is `rowPx` tall (`features/terminal/geometry.ts`: 1.5 × the font size, snapped
to whole device pixels), every row the same.

| Class | Characters | Drawn as | Fixture |
| --- | --- | --- | --- |
| ASCII | U+0020–007E | JetBrains Mono (shipped), 1 cell each | `mixed` |
| Wide (CJK) | `textCells` 2, not emoji | the fallback font scaled to exactly 2 cells (`term-wide`) | `mixed`, `frames` |
| Emoji | composed graphemes tmux 3.4 makes 2 cells | a 2-cell box, the glyph scaled to fit (`term-emoji`) | `mixed` |
| Other narrow symbols | the rest, 1 cell | a box of their cells' width | `mixed` |
| Backgrounds and inverse | a run's SGR 4x / 7 | painted: one rectangle per colour stretch, the row's full height | `backgrounds` |
| Box drawing | U+2500–257F | painted: arms from the cell's middle (light, heavy, double with closed outer corners, dashed), arcs, diagonals | `frames` |
| Block elements and shades | U+2580–259F | painted: rectangles; shades as the text colour mixed into the ground at 25/50/75 % | `blocks`, `shades`, `eighths`, `logo` |
| Sextants and legacy eighths | U+1FB00–1FB3B, U+1FB70–1FB8B | painted: rectangles on a 2×3 grid, or eighths | `sextants` |
| Powerline | U+E0B0–E0BF | painted: filled triangles and half circles, lines for the thin ones | `powerline` |

Painted means `lib/paint.ts`: one SVG per row (`term-paint`), behind its text, in cell units (a cell 60 wide,
a row 150 tall), edges snapped to device pixels, shapes that touch a row's edge reaching half a device pixel
past it (no hairline where two rows' edges round apart). The characters stay in the text, transparent
(`term-painted`), so a selection shows over them and copying gives them as they are. A line's HTML is kept
by its text and the style it starts in (`ansiToLines`), so an update parses and paints only new lines.

Besides `glyphs.spec.ts`, the suite checks the layer's cost (`scrollback.spec.ts`: a 2,000-line painted
scrollback, output streaming in, within `renderMs`) and selection (`selection.spec.ts`: it shows over a
painted background; copying gives the real characters). A fixture that cannot pass yet goes in the spec's
`KNOWN_RED` (expected to fail; one that then passes fails the run, so it must come off); none is there now.

## Architecture (layered — do not collapse)

1. `src/components/ui/` — primitives only. The only place a new visual style is defined.
2. `src/features/<name>/` — `daemons`, `sessions`, `terminal`, `conversation`, `approval`, `push`, `pairing`, `install`, `voice`, `mentions`, `inbox`. Each owns `api/`, `hooks/`, `components/`, and pure logic in `model/` (e.g. `sessions/model/`: how sessions are classified, filtered, grouped, counted, and the list's URL params). No imports into another feature's internals; share through `src/lib/`.
3. `src/routes/` — compose features into pages. Layout and wiring only:
   - `__root.tsx`: the app shell (sidebar from `lg`, bottom tab bar below it, hidden on a phone while a session is open).
   - `_sessions.tsx`: pathless layout holding the session list (validates its URL search params); `_sessions/index.tsx` (`/`) and `_sessions/d.$daemonId.s.$sessionId.tsx` render beside it from `md`, instead of it below.
   - `daemons.tsx`, `pair.tsx`.
4. `src/lib/` — shared by every feature: `daemons/` (the persisted daemon list + `useDaemonClient`, and `useNodes`: the computers joined to a daemon, which the sessions and daemons features both use), `api/` (client factory, generated `schema.d.ts` + `types.ts` aliases, `stream.ts`/`streams.ts`), `runtime-config.ts`, `query.ts`, `agent-state.ts`, `web-analytics.ts` (Cloudflare's beacon, in the public hosted app's build only, its reports reduced to route patterns: `deploy/README.md`).
5. `src/sw.ts` — the service worker (own tsconfig: `tsconfig.sw.json`).
6. `src/demo/` — the demo build (`--mode demo`, entry `demo/main.ts` instead of `main.tsx`; no service worker; routes by the URL hash, since a static site serves it as one page). It changes no app code: it answers the app's requests and its `/v1/stream` socket for a made-up daemon address in the page (`server.ts`, `socket.ts`), from a `World` of scripted sessions (`scenes/`: each a session, its screen and conversation, and the steps it plays when approved, denied or messaged). Nothing goes out; every visit starts fresh. Fixtures keep the daemon's real shapes (typed from the schema); a new API field the app needs must be added to `scenes/session.ts`.

Split before 250 lines or once a file mixes two domains.

## Layout and navigation

- Three widths: phone (one pane at a time; the panel-left at a pane's top-left opens the one level up as a drawer: the list over a session, the sidebar over the list), `md` (list and session side by side), `lg` (plus the sidebar: the layout switch, views, devices each with its folders, sources, with counts). Panes are `Pane`/`PaneHeader`/`PaneBody` from `components/ui/pane.tsx`: a fixed header (back on phones, title, subtitle, actions) and a body that scrolls on its own.
- The layout is one value per browser (`lib/layout-prefs.ts`, `useLayoutPrefs.layout`): `full` (sidebar, list and session), `list` (list and session) or `session` (session only), plus the one Alt+F goes back to (`previous`). It is changed only by the switch (`LayoutSwitch`, `routes/-panes.tsx` `PanesSwitch`: a segment per layout, drawn as it, the current one filled and named, with a tooltip; three where the sidebar can dock, two from `md`, none on a phone), Alt+F (session only ↔ the layout before) and ⌘K. A narrow screen shows the widest layout it can (`shownLayout`: the sidebar docks only at `SIDEBAR_QUERY`, the list beside only at `SPLIT_QUERY`) and never writes that back, so an unfolded Fold shows the saved one. The switch is always at the top-left of the leftmost visible pane, in every layout: the sidebar's, else (compact, `PanesLead`) the list's or the session's header, before the panel-left; a header's title truncates before its controls do. `usePanes` says where each pane is wherever docking is decided.
- What the layout hides is one drawer (`lib/layout-drawer.ts`, `useLayoutDrawer`), laid out as the panes would dock: the sidebar and the list side by side when both are hidden (the list's drawer in `_sessions`, the sidebar put in its `sidebarSlot` by the root shell), else the sidebar alone (a push drawer from the root shell; the page it pushed is put back when it goes). The panel-left (`ShowPanes`, `ShowPanesButton`), beside the switch at the top-left of the leftmost pane showing, opens it: "Show the sidebar", or "Show sessions" when the list is hidden too; it carries the Needs-you count, or a dot when a daemon wants a look. The drawer has the switch at its top-left (the sidebar's), closes on a session picked (rows replace the page it opened on), Esc, a tap outside and Back (`useDrawerHistory`), and a swipe right on the session (the pager's first page) or the list pulls it. Nothing ever resizes the session for it, so a terminal refits once (its 250 ms settle). The session menu offers the browser's full screen where `document.fullscreenEnabled`, apart from the layout; while it is on the item reads "Exit full screen" (`useFullScreen`, from `fullscreenchange`), and Esc leaves it as the browser does (never intercepted).
- What the session list shows (view, device, folder, source, grouping, search) lives in the URL search params of `_sessions`, so back, reload and links keep it; links into a session pass `search={true}` to keep it. The grouping chosen last is the default (`useListPrefs`).
- Leaving a list and coming back lands where the reader was: the list stays mounted beside a session, and `useScrollMemory` restores the position per query when it shows again.
- A page's secondary actions go in its "⋯" menu; features add entries through the menu's `items` slot (e.g. terminal settings into the session menu).
- Sessions are classified only through `sessions/model/facets.ts` (status, device, folder, agent, source); lists, filters and counts never re-derive them. Hierarchy is device → folder → folders inside it: `groupEntries` gives a device group `sections` in tree order (`model/folders.ts`, `nestFolders`: depth, parent, name below the parent), `facetsOf` gives each device its `folders`, and a group's `implies` tells rows what not to repeat.
- Read state, hiding and archiving are the daemon's (`session.unread`, `session.hidden`, `session.archived_at`, shared by all devices): `useSeenWhileOpen` reports the open session as read; `useMarkRead` / `useHideSession` (any daemon, optimistic) and `useArchiveSession` back the actions. Where a session is listed is `placeOf` (listed, hidden, archived; the last two only in their own view, reached from the sidebar or the filter menu, never the tabs); an archived session's page is its conversation, with no input bar.
- `DropdownMenu` is not modal: a dialog opened from a modal menu's item would leave the page unclickable after closing.
- Which agent a session is (Claude Code, Codex…; `agentOf`, from `session.runtime`) is said by shape, never by color: color means state here. `AgentMark` (`sessions/components/agent-mark.tsx`) gives each agent its own glyph; rows show it only while the list holds more than one agent (`agentsDiffer`, like accounts), the session header always names the agent first, and agents are a filter, a grouping, a sidebar section and phone chips only when there is more than one. The New session dialog starts on the agent started last (`useNewSessionPrefs`).
- Where a session belongs (its project, its folder, or Other) is decided only by `model/belongs.ts`: the hub's project (whatever gave it) or its repository, else its folder unless that holds no project (home, `/`, temp, none, a workspace: `workspaces.ts`), else Other. The list grouped by project, the chips and their dialog, chip membership, the sidebar's projects, ⌘K and the search's `project:` term all read `belongingsOf(every known session)`, never a filtered part (a workspace is known only from the others); nothing else derives a project or folder group.
- Where a session is listed under its device is `homeOf` (`model/places.ts`): a project someone set, else its repository from `session.git` (its main folder, holding subfolders and worktrees; `worktreeOf` lists a worktree under it by branch), else its folder; `folderLabel` and the sidebar's folders use it, `nestFolders` takes an explicit parent (`under`) for worktrees, `PlaceIcon` shows the kind.
- Usage: `useMachineUsage` (`lib/daemons/`) reads `/v1/usage` of every paired daemon; a machine over a limit gets a `WarningMark` by its name in the sidebar, the Daemons page lists each one's usage (`UsageList`) and this page's own (`Diagnostics`, from `lib/diagnostics.ts`: frames counted in `stream.ts`, draws in `TerminalView`; `watch-page.ts`: Event Timing, long frames, a size sample a minute); nothing shows while all is well. This page's own alerts (`diagnostics-alerts.ts`) are said in Daemons › Diagnostics; only a severe one that an action fixes (the GPU lost, a heap near 1 GB, the page's own elements tripled) reaches the mark by the app's name (`WebUsageMark`), dismissible for that condition (`dismissed-alerts.ts`). A slow key or tap is kept as its event and where it landed (`describeTarget`: the nearest `data-component`, a fixed phrase the app gives an area, and the role pressed), never text, a value or a label (labels carry session names). The page's growth is measured against it once settled (a minute in, a session shown), without the views whose history is bounded by design (`data-bounded`: terminal scrollback, a conversation). The service worker logs what it does with pushes (`lib/push-log.ts`: each push shown or clearing, the tags it was asked to close, the notifications then on screen by tag and time, what it closed and what `keepOne` held back; taps and dismissals), in an IndexedDB ring (`lib/idb-ring.ts`, the newest 200); the app posts new records to the daemon each came from (`POST /v1/diagnostics`, source `push-clear`, `useReportPushLog`: at start, on resume, when the worker says it logged) and Daemons › Diagnostics shows them (`PushLogTable`). Tags, ids and times only, never a notification's title or body; a trigger's tag loses its name.
- Teams: a session's role and project (`session.team_role`, `project`, kept by the daemon, set by agents over MCP or by the owner) show first in its row's meta line and its header's subtitle; its actions offer Team (`TeamDialog`, titled "Team · <project>" with its colour dot: "This session", its role and note saved on leave or Enter and its project only on a pick from the list or Enter (`SuggestInput floating`, a name no session has marked "new project"; leaving otherwise puts the project back), then "Team": its members (a click opens one) and its recent tasks over 24 h or 7 days, `useProjectActivity`; the playbook in a last line). A project group's header opens the Team part alone (`ProjectTeamDialog`).
- A session whose source names no machine is under `NO_ENVIRONMENT` ("No environment"), said as it is; where `capabilities.place`, its actions offer Move (`PlaceDialog`: device and folder, or Detect from its whole log), and the daemon then reports it there (`session.placement`).
- Grouped by project, the list keeps a stable order (`model/project-order.ts`): nothing moves for what sessions do (state shows as icons, badges, counts). Projects in the owner's order, kept on the hub (`/v1/project-order`, `useProjectOrder`), the rest after by name, then folder groups by name, then Other; inside a group a PM or a lead first, then by creation. A project's header is dragged by its ⋮⋮ handle (hover, a mouse; the keyboard) or held on a touch screen, or moved with Move up / Move down in its "⋯"; nothing else on the header listens, so a wheel or a swipe over it scrolls the list.
- Each project has a colour, one of six soft hues (`--color-project-N`, `-soft`, `-ink`; `components/ui/project-hue.tsx`), kept on the hub (`/v1/project-colours`, `useProjectHue`): the hub gives a project its hue as it first lists it, and the owner changes it in a project group header's "⋯" (Colour, `ProjectHuePicker`). It shows as a dot on the list's project headers and the sidebar's Projects (`ProjectIcon`), and tints the project tag in the session header and ⌘K (`ProjectTag`); a project with none yet, or a hub too old to keep them, shows neutral. A colour never means a state.
- The list's group and folder headers fold what is under them (`useListPrefs.collapsed`, keyed by `foldKey(grouping, group, section)`); a search unfolds everything. The sidebar's device fold (`folded`) is separate.
- A session opened from the list stays in it once it no longer matches (`useOpenedHere` remembers what was opened per query, `model/kept.ts` puts it in a last "Just opened" group). `useRowMoves` (`features/sessions/hooks/`) slides rows to their new place when a row changes group or comes or goes (it measures only then), also after the list was hidden (phones).
- Live mode (`features/voice/live`): hands-free voice into the message box of the session page in front. A local VAD (Silero, `@ricky0123/vad-web`, its model and ONNX Runtime's wasm from a pinned CDN, loaded when Live is first turned on) cuts speech at ~1 s pauses and drops non-speech, short and quiet segments; only those segments go to `/v1/asr?source=live`, and only while listening. `LivePipeline` routes them (short and only a command: send/pause/clear/undo; long and ending in send: appended, then sent; else text), lands them in order, and holds later uploads behind a short segment, so nothing said after "pause" leaves the device; paused, only the on-device spotter listens, for "resume" (or a tap, Alt+L). Spoken commands are heard on the device (`kws.ts`, `kws.worker.ts`: sherpa-onnx KWS via `@sherpaw/kws`, the zh+en 3M model, 13 MB, from a pinned Hugging Face commit into Cache Storage on first use; its WebAssembly from a pinned CDN, rewritten in `vite.config.ts` so it is never bundled; the Worker is terminated when Live is off): a short segment it is sure of acts without upload; else the segment is transcribed with `hint=command` and matched, tolerant of known mishearings (`commands.ts`). The languages listened for are a per-browser choice (Daemons page, English by default); each is a pack of data (`live/packs/<lang>.ts`: the words, how speech to text mishears them, the spotter's tokens), and the code holds no words of its own. For a phone on a car's Bluetooth (per browser, `audio-prefs.ts`, Daemons › Live in the car): the microphone Live opens (`mic.ts`: default, the phone's own or a Bluetooth one, picked from `enumerateDevices`; MicVAD's `getStream`), voice processing on or off, and, while Live and Read aloud are both on, the phone's media controls held all along (`car-media.ts`: a looping WAV keeps Chrome's media session: a 25 Hz tone at -60 dBFS, over Chromium's audible threshold (-72.25 dBFS; a session needs an audibly playing element) and under hearing; the phone's own voice has no media element, so the loop carries the session then, and a pause of it during that voice is not the user's; the controls held once it plays, "playing" all along, a pause of it the page did not make taken as the user's and the loop played again; `media.ts` owns the metadata and the action handlers, set only while held or while the hub's voice plays, set again after each of its mp3s; play/pause stops what is said, else plays the latest, and says so when there is nothing); `status.ts` says what is in use. While held, `media-log.ts` tells the hub what the controls did (`POST /v1/diagnostics`, source `media`: handlers set, actions and what they did, the loop's and the mp3s' events, playback state, page visibility; event names, states and error names only, never content), batched every 5 s or 20 entries. The page registers itself as the target (`setLiveTarget`) and the terminal feature's `draftBox` as how its box is written to; `InputBar` registers its Send (`submitters`), so a spoken send is the same send.
- The Inbox (`features/inbox`, route `/inbox`): the owner's ideas and to-dos across projects, kept on the hub (`/v1/inbox`, the first daemon, as the project order). First in the sidebar with its open count; beside the list where a session opens (from `md`), a sheet on a phone. Rows: done box, text (edited in place: Enter saves, Esc cancels), project tag, age or due (`model/due.ts`, from the hub's `due_state`; overdue in a warning ink), "⋯", a ⋮⋮ handle (`useSortableRow`: a mouse, the keyboard, a held finger). "Due soon" (due or overdue, then the next 7 days) sits above the rest, which keeps the owner's order. Every PATCH sends `if_version`; a 409 puts the item as it is now and says so in its row, offering the owner's change again, never resending it alone. Hand to… (`hand-picker.tsx`): a project, then a role held in it (whoever holds it) or one session; the project's default hand-off role (`lib/handoff.ts`, also set from a project header's "⋯") is picked to begin with. A due date (quick choices, `DatePicker`, an optional time) reminds, or hands off to a target picked the same way. Quick-add: Alt+N anywhere (`quickAdd`), inline at the sheet's top on a phone. An `inbox` push is tagged per item and opens `/inbox?item=<id>`, that row brought into view. No role name is written into the app: roles are the owner's words.
- Mentions: `@` in the message box (and in a quote's reply) offers sessions to mention (`features/mentions`: its team, the ones mentioned lately on this browser, every other project folded; typing searches them all) and inserts `@role@project (id)`, parsed back in the same place (`mentionsIn`). The menu is a primitive, `useTokenMenu` (`components/ui/token-menu.tsx`); the session route hands `InputBar` the source as its `mention` slot.
- Plan usage (`features/plan-usage`): the Claude and Codex subscriptions the machines' CLIs are signed into, as the hub reports them (`usePlanUsage`, the first daemon, as the project order). A chip (`PlanUsageChip`) in the docked sidebar's head, a line per account, else in the list's header, the account nearest a limit: numbers and time to reset only, the warning tone from this device's threshold (`usePlanUsagePrefs`, 70/80/90%), danger while limited; a tap opens every window with its exact reset (`Popover`). When a window passes the threshold or an account is limited, the chip grows into the island (`PlanUsageIsland`, `ui/island.tsx`): a dark pill below the header, over the page, so nothing resizes; once per subject while it lasts (`subjectKey`, remembered on the device, forgotten when it ends), held 6 s, a tap settles it; its shapes morph through a view transition (`morph`), at once without one, and under reduced motion it never grows (the chip's tone is the highlight). Daemons › Plan usage lists every account (`PlanUsageSection`: provider, plan, a short form of its hashed key, its windows with their labels as the hub gives them, per-model ones apart, its machines; a missing figure "—", an old reading with its age) with the on/off switch, the hub-wide setting `plan_usage.enabled` (`PATCH /v1/settings` on the hub; off, the hub lists no account).
- Pictures, videos and shared files in a conversation are one gallery (`features/conversation/model/gallery.ts`, `conversationMedia`: what items show, `itemMedia`: an item's `media`, files by their path as written and images inside a tool's result by item and place, or an older daemon's `images`; then files the agent shared, `kind: 'shared'`), opened large in `ImageViewer` (a video is the browser's own player, `ui/video.tsx`; it pauses when the viewer moves on). Every file is fetched with the daemon's token as a blob, whole (the daemon serves at most 25 MB), and shown from an object URL (`lib/use-object-url.ts`), so a video seeks within it and no token goes in a URL. A picture loads with its thumbnail; a video (an item's, an old daemon's or a shared one) is a tile that fetches nothing (`VideoTile`: ▶, its name, "Video"), loaded only when opened in the viewer (a spinner meanwhile), since agents name recordings often and a phone may be on mobile data. What cannot show says so quietly (`model/media-state.ts`: 410, or a 404 once shown, "File no longer there"; 413 "Too large to show"; 409 its machine away, with Retry; a 404 never shown or a 415, nothing), and the gallery counts only what can (`useUnshownMedia`). A shared file that is not a picture or video is a `FileCard` with Download (`lib/save-blob.ts`: re-typed `application/octet-stream`, saved, never opened: a blob URL has the app's origin); past `expires_at` or on a 404 it reads "Expired".
- Quoting: `SelectionAction` (`components/ui`) puts a button under text selected inside an area; the session page uses it on its views to add a quote to the draft (`useDrafts` quotes, `features/terminal/quotes.ts`), which `InputBar` shows inside the message box, above what is typed (`QuoteCards`: a line each, opening to a reply of its own) and sends first, each quote followed by its reply.
- What can be done to a session is defined once, in `SessionActions` (render prop + its dialogs); a list row offers it as a swipe tray (`SwipeActions`) and a hover menu, the session page as its "⋯" menu.
- Sidebar entries mark themselves current from the list's search params (`isCurrentScope`, `data-current`), because the router alone cannot tell while a session is open.
- A session's terminal and conversation are two pages of `Pager` (`components/ui/pager.tsx`: the pages follow a sideways finger and, let go, land in a short slide on the page its distance and speed point to, which is shown and takes taps at once; a swipe right on the first page opens the drawer; an inner scroller that can still scroll sideways takes the swipe). Swipes (`Pager`, `SwipeActions`) share `components/ui/gesture.ts`: a swipe is told from a scroll by its first pixels (up to about 50° off level) and stays one however the finger drifts, and a flick (at least 0.4 px/ms over 40 px; a press held still before it counts too) like a long swipe, while a quicker twitch counts for nothing; a released swipe lands at the finger's speed in 110–190 ms. The drawer (`components/ui/drawer.tsx`) follows a swipe left and closes, leaving a swipe right, or one on a row showing its actions (`data-swipe-open`), to the row.
- The input bar is one row (keys toggle, message box, Send); its text is a per-session draft in `useDrafts` (persisted), cleared once sent; where the conversation is shown, at once instead: the message waits, faded, at the conversation's end until a prompt there has it (`lib/outbox.ts`, `useOutgoing`), says so after a minute without, and, if it could not be sent, stays there said so (`Not sent: …`, Retry, Dismiss); a prompt the conversation has but the agent has not taken in (`pending`: the Claude desktop app holds one from muxtower until Deliver is clicked there) shows where it waits, and after 10 minutes offers to be sent again; for a desktop-app session the box says so in one quiet line (`composerNote`), with Continue in terminal after it (`ContinueLink`; also in its "⋯" where `capabilities.continue_terminal`, greyed with `continue_blocked`): `ContinueDialog` says what happens, looks for its transcript (GET /continue), shows the run's progress and how it ended (Retry when the pane did not start), and opens the pane session it became; `KeyPad` opens above it, laid out like a keyboard (arrows as an inverted T, Enter at the right edge). Keys fire on pointer down without taking focus, so the phone keyboard stays as it was.

## Daemons are plural

A daemon can also be a hub: other computers' daemons join it as nodes (`docs/design.md` › Hub and nodes), and their sessions come in its own list, each with `node` set (the New session dialog can start one there; one whose node is away is `offline`, shown dimmed and read only). The Daemons page lists a daemon's nodes and makes the code a computer joins with. Accounts are shown (a row's place line, a filter, a grouping) only when the sessions run as more than one (`accountsDiffer`).

- The daemon list lives in `src/lib/daemons/store.ts` (Zustand, persisted): `{id, name, url, token, preset?, streamAuth?, pushSubscriptionId?}`. Nothing about a daemon is baked into the bundle; defaults come only from the runtime `/config.json`. Selectors that build arrays use `useShallow`.
- Get a client with `useDaemonClient(daemonId)`; never construct `fetch` calls or URLs in components.
- Every query key starts with `['daemon', daemonId, ...]`. The Inbox merges per-daemon queries; it never assumes one daemon.
- One `/v1/stream` socket per daemon, owned by `src/lib/api/streams.ts` (auth order: same-origin cookie, subprotocol, query token), which writes frames into the query cache. Components subscribe with `useStreamSubscription`; they never open sockets. Queries poll only while their daemon's stream is down.
- What a session page offers comes from `session.capabilities` (screen or conversation, accepted keys, resize, rename, terminate), never from `session.source`.
- Features compose through slots, not imports: e.g. `DaemonCard` takes `actions`, and the daemons route passes pairing and push UI into it.

## Styling — token discipline

- Colors, font sizes, radii, shadows only from `src/styles/tokens.css` (`@theme static`, so tokens read from JS exist too). No hex, no `rgb()`/`oklch()`, no Tailwind palette classes (`bg-zinc-900`), no arbitrary visual values (`text-[#fff]`, `rounded-[3px]`), no inline `style` colors. Arbitrary layout values (`max-h-[90dvh]`) and variants (`data-[state=open]:`) are fine. Libraries that need concrete colors (xterm.js) get them from `lib/css-color.ts`, which resolves tokens. Enforced by `npm run check:tokens` (`scripts/check-tokens.mjs`) in lint.
- **Features say what a thing is; components/ui decides how it looks.** Outside `src/components/ui/` a class
  string holds layout only (display, flex and grid, gap, padding and margin, size, position and inset,
  overflow, z, alignment, truncate, whitespace), and a look comes from a named intent or a component:
  `ink.*` for text (meta, hint, body, label, strong, code, link, the tones…), `look.*` for boxes (panel,
  frame, list, pill, hoverRow, bar, rule…), the stateful intents (`listItem`, `treeLink`, `liveRow`,
  `bubble`, `quoteCard`), and components with their variants (Button, Input, Banner, Card, Chevron,
  StatusIcon…), all in `components/ui/intents.ts` and its neighbours. The builders behind them (`text`,
  `box`, `motion` in `styles.ts`) are ui-internal. An element takes at most one `ink` and one `look`
  (`ink.count` may join); a component with a look of its own takes variants, not intents. **Features pick
  an intent; if none fits, add one in ui, merging rather than adding a near-duplicate.** A new intent says, in its
  comment, which existing intent it is not and why (`/** … Not \`hint\`: … */`), so the next one reuses
  before it adds.
- **No native controls in features**: `<button>`, `<input>`, `<select>`, `<textarea>` and a styled `<a>` are
  Button, Input, Select, Textarea, Checkbox, Switch, FilePicker, TextLink. `Button variant="plain"` wraps
  custom content whose look comes from other primitives; it adds none of its own.
- **Spacing scale.** Gap: 0.5 stacked lines, 1 tight, 1.5 an icon and its label, 2 default, 3 sections, 4 a
  page's blocks. Padding: 0, 0.5, 1, 1.5, 2, 3, 4, 6, and 8 or 10 to indent past an icon. Margin: 0, 0.5, 1,
  1.5, 2, 3, 4, auto. Nothing negative; arbitrary values only for the safe area (`env(...)`). Controls are
  40 px (icon buttons, inputs, a single-line composer, the Live row) or 32 px; bars pad `px-2 sm:px-3`,
  `py-2`. Other steps, and anything a value computed at runtime needs, live inside a primitive.
- Enforced by `check:tokens` (`scripts/check-tokens.mjs`: colors; `scripts/check-styles.mjs`: layout-only
  class strings, the spacing scale, no native controls, no import of the builders, one ink and one look per
  element, no intent on a component with its own look; outside `components/ui/` and `lib/ansi.ts`). It has
  no allowlist; a case it cannot express becomes an intent or a variant in ui.
- Not checked, still the rule: don't build a primitive-shaped component in a feature (a chip, a field, a
  toggle line): extend or add the primitive; prefer a variant to a new role; a session state's color is its tone (`stateTone` maps a
  state to it), never a hand-picked one; keep the roles few.
- Need a new color? Add the token (both themes) first.
- Agent state colors are tokens too (`--color-state-permission`, `--color-state-question`, `--color-state-busy`, ...).

## Component decoupling / React

- Composition over prop lists; one responsibility per component; check `components/ui/` before styling something new.
- Function components and hooks only. Hooks named `use-kebab-case.ts`.
- `useEffect` only to sync with external systems (the terminal DOM, service worker, socket); never to fetch or derive state.
- No prop drilling past two levels.

## State management

- Server state through TanStack Query, one hook per resource inside its feature. Mutations invalidate or patch the right `['daemon', id, ...]` keys.
- Client state (daemon list, UI prefs) in Zustand; local `useState` first.
- Server data never goes into Zustand.

## Interaction

- Nothing acts as a pointer or finger goes down: a touch that starts a scroll would set it off. An action fires on a tap (on release, the finger still, no scroll), or after a hold; `scripts/check-styles.mjs` fails a feature with any other `onPointerDown`, an `onTouchStart`, or a pointerdown/touchstart listener that is not passive.
- Presses go through `components/ui`: `Button` (a click, which browsers do not fire after a scroll); `ui/press.ts` on React Aria's `usePress` for a key that repeats while held (`useRepeatPress`: a tap sends once on release, held still 350 ms it repeats, a move or a scroll sends nothing), a hold (`useHold`) and a card that takes a tap or a swipe (`useTapOrSwipe`). Menu triggers (`DropdownMenuTrigger`) open on a tap for a finger or pen; a mouse keeps Radix's open-on-press.
- On pointerdown a feature may only keep the focus (`keepFocus`: a phone's keyboard stays up); it never stops a scroll.

## Accessibility, loading, error states

- Every interactive element has an accessible name; icon buttons get `aria-label`.
- Query loading/error/empty go through `src/components/query-state.tsx`; a disabled query is not "loading". Loading shows nothing for 150 ms (`SHOW_AFTER_MS`), then the caller's `skeleton`: placeholders in the shape of what comes, from `Skeleton` (`components/ui/skeleton.tsx`: line, title, badge, icon, control, block; pulsing, still under reduced motion), laid out as the real thing so nothing moves when it arrives (`SessionSkeleton`, `ListSkeleton`); without one, a quiet line (`Loading`). A failed page (`page`) is a centred notice with Retry; elsewhere a Banner. Before the app's script runs, `index.html` shows its own boot screen in #root (token colours, light and dark), replaced by the first render.
- A daemon that is unreachable or rejects its token shows a per-daemon banner, not a global failure.

## Testing

- Vitest + React Testing Library; network mocked with MSW at the HTTP boundary (`src/test/handlers.ts`), generated from the same schema types.
- Every `features/*/api` hook has a test; every `components/ui` primitive has a render test before a second feature uses it.
- Playwright E2E in `e2e/`: the terminal suite (`make glyphs`: glyphs, scrollback cost, selection; above), against Vite's dev server.
- How fast a click shows (`e2e/switch-speed.spec.ts`): on a production build of the demo, a session switch in an 80-session list must paint within `BUDGET_MS` of main-thread CPU (a trace's task CPU time from the click's first input event to the paint showing the row marked and the new header; median of several clicks), never wall clock. `MUXTOWER_SWITCH_REPORT=1` prints every interaction (session switch, chip click and wheel, a sidebar project) at 28 and 80 sessions, CPU ×1 and ×4; `MUXTOWER_SWITCH_URLS=a=<url>,b=<url>` measures builds side by side, a click on each in turn (the machine's load moves numbers more than a change does); `MUXTOWER_SWITCH_PROFILE=1` builds with React's profiling build, unminified (`MUXTOWER_PROFILE=1`), and adds each component's render time on the click's way to its paint, why the big ones drew, and a CPU call tree. The demo's `?sessions=<n>` adds made-up sessions until its hub lists n.
- Keep a click cheap: a list row draws again only when its own session or selection changes (read the router with a `select` of what is used, never a whole match; `defaultStructuralSharing` keeps equal values); what a row offers on demand (menus, the swipe tray) is made when first wanted; a session's views come in a render after its header.

## Forbidden

- Raw colors or palette classes outside `tokens.css`; arbitrary Tailwind values.
- New visual primitives outside `components/ui/`.
- Cross-feature internal imports.
- Hand-written API types or URLs; anything not going through the generated client.
- Hand-rolled `useEffect` + `useState` fetching.
- A second state library or Context store for client state.
- Any URL, token or hostname baked into the bundle or `.env` files committed with values.
- UI strings in any language but English.
- Personal names, hosts or predecessor-project references (see root `AGENTS.md`).
